# 検品のやり方

**AIが「できました」と言っただけでは合格になりません。**
このアプリは手元でコンパイルできないので、AIの言葉はいつでも推測です。

## 合格の証拠として認めるもの

| 確かめたいこと | 認める証拠 | 認めない証拠 |
| --- | --- | --- |
| コンパイルが通る | CIの `test` ジョブが success | 「ビルドは通るはずです」 |
| テストが通る | ログの `Executed NN tests, with 0 failures` | 「テストを書きました」 |
| 画面の見た目 | 実機のスクリーンショット | コードを読んだ推測 |
| レシートの精度 | レシートの写真 + 読み取り結果の画面 | 「精度を上げました」 |
| 配信できた | `UPLOAD SUCCEEDED` とビルド番号 | 「アップロードしました」 |
| 同期する | 2台の画面の写真（別々のApple ID） | 「同期するはずです」 |

## 証拠の取り方

### CIの結果

```bash
gh run list --limit 5
gh run view <実行ID> --json jobs -q '.jobs[]|"\(.name)\t\(.conclusion)"'
```

テストの件数:

```bash
gh run view <実行ID> --log | grep -oE "Executed [0-9]+ test[s]?, with [0-9]+ failure[s]?" | tail -1
```

`tasks.json` の `evidence` には、**実行URLとテスト件数を両方**書いてください。

### 失敗した理由

```bash
gh run view <実行ID> --log-failed | grep -E "error:" | sort -u | head -20
```

### 配信されたビルドの中身

CIのログに、実際にアプリへ入った値が出ます。
ここが `1.0 / 1` だったら、Info.plistが上書きされている合図です（過去に起きた事故）。

```bash
gh run view <実行ID> --log | grep -A4 "archive Info.plist"
```

## `passes` の書き方

`tasks.json` の各タスクには「何をもって合格とするか」を書きます。

| 悪い書き方 | 良い書き方 |
| --- | --- |
| 精度が上がる | このレシートで合計が2,080になるテストが通る |
| 共有できる | 2台の端末で同じ支出が表示されたスクリーンショットがある |
| きれいになる | 実機の画面写真で、背景が白・文字が黒になっている |

**測れないことを `passes` に書かないでください。** 測れないなら人間に判定を依頼します。

## 差し戻す条件

次のときは、迷わず不合格にしてください。

- CIが赤、または実行されていない
- テストの件数が前より減っていて、理由が書かれていない
- `passes` に書かれた証拠が `evidence` に無い
- 実機での確認が必要なのに、されていない
- `Docs/requirements.md` `Docs/safety.md` `evals/acceptance.md` が書き換えられている
- 頼んでいない変更が混ざっている

## 人間にしか判定できないこと

次はAIには判定できません。人間に依頼してください。

- 見た目の好み（色、余白、文字の大きさ）
- レシートの読み取り結果が実物と合っているか
- 2台での共有が本当に動くか
- App Store Connect / CloudKit Console の画面の状態

依頼するときは、**何を見て、どうなっていれば合格か**を一緒に伝えてください。
「確認してください」だけでは、人間も判定できません。
