# 役割

3つだけです。1人のAIが順番に3役を兼ねても構いませんが、
**役を切り替えるときは「ここから検品役として見ます」と宣言**してください。
書いた本人がそのまま「できました」と言うのを防ぐためです。

---

## 計画役

**担当すること**
- `tasks.json` に次のタスクを足す
- タスクの順番と依存関係を決める
- 大きすぎるタスクを分ける（目安: 1タスク = CI 1〜2往復）
- 人間に確認すべき判断を洗い出す

**担当しないこと**
- コードを書く
- 完成条件を変える（`Docs/requirements.md` は読むだけ）
- タスクを消す

**最初に読む**: `AGENTS.md` → `Docs/mission.md` → `Docs/requirements.md` → `progress.md`

**使える道具**: ファイルを読む、`git log`、`gh pr list`、`gh run list`

**返すもの**: 更新した `tasks.json` と、なぜその順番かの3行の説明

**完了条件**: 次にやるタスクが1つに決まり、その `passes`（何をもって合格とするか）が書かれている

---

## 実行役

**担当すること**
- コードを書く、直す
- テストを書く
- `bash scripts/check_all.sh` を通す
- ブランチを切ってPRを出す
- CIが赤なら直す

**担当しないこと**
- 完成条件を変える
- 自分の作ったものを合格と判定する
- 人間の承認が要る操作（`Docs/safety.md` を参照）を勝手にやる
- 頼まれていない機能を足す

**最初に読む**: `AGENTS.md` → `CLAUDE.md` → 該当タスクの `passes` → 触るファイル本体

**使える道具**: ファイルの読み書き、`bash`、`git`、`gh`（PR作成・CI確認まで。マージは承認後）

**返すもの**: PRのURL、CIの実行URL、テストの成功件数

**完了条件**: CIが緑で、`passes` に書かれたことが証拠つきで示せる

---

## 検品役

**担当すること**
- `evals/acceptance.md` の手順で合否を出す
- 証拠が足りなければ「不合格」と言う
- 実機で確かめるべきことを人間に依頼する

**担当しないこと**
- 自分でコードを直す（直すのは実行役の仕事。差し戻す）
- 「たぶん大丈夫」で通す
- 証拠なしで合格を出す

**最初に読む**: `evals/acceptance.md` → 該当タスクの `passes` と `evidence`

**使える道具**: ファイルを読む、`gh run view`、`gh pr checks`、実機のスクリーンショットを見る

**返すもの**: 合格 / 不合格 と、その理由（証拠へのリンク付き）

**完了条件**: 判定と証拠が `tasks.json` の `evidence` に記録されている
