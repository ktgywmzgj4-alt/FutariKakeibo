# App Store のスクリーンショットの案（D9・T-066。2026-10-22）

利用者の方針（D9）: CI のシミュレータで、架空のデータで撮る。**まず撮る画面と見出しの案を見せる。**
実在の家計・氏名・レシートを使わない。実際には使えない機能を写さない。価格・特典の条件をスクリーンショットとサブタイトルに入れない。
撮影用のデータや動きが、ふだんの利用で出ないようにする。

**この文書は案です。撮影のための UI テスト・ワークフロー・撮影用のデータは、まだ作っていません。** 利用者が画面と見出しを確かめてから作ります。

1つの大きさにつき最大10枚。`.png` か `.jpg`、透明（アルファ）を含めない。

## 3. 作り方（案。ワークフローを足す前に文面の承認をもらう）

- **撮影用のデータは、開発用のビルド（Debug）にだけ入れる。** `#if DEBUG` の中に置き、起動の引数（例 `-screenshotDemo`）があるときだけ、端末の保存・iCloud・通知を使わず、メモリの中の架空のデータで動く。
  TestFlight と App Store に出すビルド（Release）には、データも切り替えも入らない
- 撮影は UI テスト（XCUITest）の新しいターゲットで行い、**いまのテスト（`FutariKakeibo` の scheme の単体テスト）とは別の scheme にする。** `ios.yml`（CI と配信）は変えない
- 新しいワークフロー `screenshots.yml`（案）:
  - 手で起動したときだけ動く（`workflow_dispatch`）。macOS のランナーで、シミュレータ用にビルドする（署名なし・Secrets を使わない）
  - 日本語・日本の地域で起動し、ステータスバーを 9:41・電池満タンにそろえる
  - iPhone 17 Pro と iPhone 17 Pro Max で撮り、透明を除いた PNG にして、実行の成果物（Artifacts）に置く。App Store Connect には送らない
  - 所要は CI と同じくらい（10〜20分）の見込み
- 撮った画像は、利用者が目で確かめてから App Store Connect に入れる（R9）
