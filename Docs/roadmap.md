## いま分かっていない、いちばん大きいこと

### 別々のApple IDで共有を試していない

要件の完成条件3は「**2台の端末（別々のApple ID）**で共有が動くことを確認済み」です。

確認できているのは iPhone 13 mini と iPhone SE2 の2台ですが、**どちらもご自身の端末です。**
同じApple IDでサインインしていた場合、`CKShare` の本当の経路（相手のiCloudから
共有データベースを読む）は**一度も通っていません。** 自分の持ち物を自分で読んでいただけになります。

実際の使い方はお二人、つまり**別々のApple ID**です。CloudKitの共有で難しいのは
そこから先で、参加者の権限、共有データベースの読み書き、`acceptShare` の挙動が
同じアカウント同士とは別物になります。

**これが分かるまで「共有は動く」とは言えません。** 最優先。

| --- | --- |
| やること | パートナーの端末（別のApple ID）で合言葉を入れ、同じ家計簿が出るか確かめる |
| 誰が | 人間（私には端末もApple IDもありません） |
| 合格 | 別アカウントの端末に同じ支出一覧が出て、そこで足した支出が元の端末にも出る |
| 外れたら | エラーの全文を撮って渡してください。`CKError` の番号から原因を追います |

## 落とせないもの（データを失わないこと）

### R-1 発行した側が、アプリを消すと家計簿を失う

`refreshFromCloudIfConfigured` は、手元に家計簿と `cloudLocation` の両方が無いと
**何もせずに戻ります**（`AppStore.swift:739`）。新規インストールはどちらも持ちません。

参加した側は戻れます。`joinSharing` が `fetchSnapshot` で全部取り直して保存し直すからです
（`AppStore.swift:639-656`）。**戻れないのは発行した側です。** 入れる合言葉を持っていないうえ、
合言葉は使い切りで消えます。

iCloudにデータはあるのに、手元のアプリから届かない状態です。

| | |
| --- | --- |
| やること | 発行した側が自分の家計簿を取り戻せる経路を作る。既存のゾーンを探して、そこから `fetchSnapshot` する |
| 誰が | 私（実装）＋ 人間（実機確認） |
| 大きさ | 中。`CloudKitSyncService` にゾーンを一覧する処理を足し、起動時に当たるようにする |
| 先に書くテスト | ゾーンが見つかったとき／無いときの分岐 |

### R-2 CSVは書き出せるが、取り込めない

`exportCSV` はありますが、取り込みはありません。R-1 が直るまでの保険にもならず、
機種を変えたときの引っ越し経路もありません。

## 記録の作法（変えないでください）

- 新しく分かったことは `progress.md` の**一番上**に3〜5行
- 実機で確かめることは `tasks.json` にタスクを立て、`evidence` に実行URLとビルド番号
- **「実装しました」で終わらせない。** CI・テスト件数・確認できていないことの3つを書く
